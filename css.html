CSS notes: making it readable

HTML is the structure; CSS is the look. These are the rules I learned in the course, and where the colours, spacing and layout of this site come from.

Section 1

What CSS is

CSS is Cascading Style Sheets. It is a list of rules, and every rule is a selector, a pair of braces, and one or more declarations of the form “property: value”.

one rule 
h1 {
  color: blue;       /* property: value; */
  font-size: 2rem;
}

h1 is the selector — “every h1 element on the page”. The braces hold the declarations, each one ending in a semicolon. Change that color and the main heading of all six pages changes, because they are all the same kind of element.

Section 2

Three ways to include it

Where CSS can live
WayExampleWhen to use it
External stylesheet <link rel="stylesheet" href="css/style.css"> Every real site: change once, applies everywhere
Internal block <style> … </style> in the head Only this page, usually for a quick test
Inline style <p style="color: red;"> Only that element; highest priority; avoid

This site only uses the first one: all styling lives in css/style.css. I use an inline style in a couple of demos, purely to show how it outranks a class.

Section 3

Selectors

A selector decides who a rule applies to. Five kinds cover almost everything:

css/style.css, excerpts 
/* 1. element: every paragraph */
p { line-height: 1.75; }

/* 2. class: reusable, written with a dot */
.card { border-radius: 14px; }

/* 3. id: one element per page, written with a hash */
#main { padding-block: 40px; }

/* 4. descendant: links inside .nav */
.nav a { padding: 8px 12px; }

/* 5. pseudo-class and attribute */
.nav a:hover { color: #5ce6b4; }
.nav a[aria-current="page"] { background: #5ce6b4; }
Result

A normal paragraph — line height comes from the element selector.

a class: .pill

Links get their hover colour from a pseudo-class

Things to remember
  • A class is written .card, an id #main.
  • A class can repeat; an id appears once per page.
  • Shorter selectors age better — div > ul > li > a breaks the moment the markup changes.
Section 4

Cascade and inheritance

“Cascading” means: when several rules hit the same element, the browser picks one. Roughly inline > id > class > element; at equal weight, the rule written last wins.

“Inheritance” means some properties pass down to children by themselves. Set font-family on body and all the text follows. Set border or padding and nothing follows — box properties do not inherit.

Mistake I made: the rule was there but nothing changed

Almost always a specificity problem: a later, more specific rule was overriding mine, or a missing semicolon swallowed the declaration. The quickest diagnosis is to comment the suspect rule out and reload — if the page does not change, that rule was not in charge.

Section 5

The box model

Every element is a box, four layers from the inside out: content → padding → border → margin.

margin (space between boxes)
border
padding (space inside the border)
content

By default width counts the content only, so padding and border make the box wider than asked. That is why the first rule in my stylesheet is:

css/style.css, first rule 
*,
*::before,
*::after { box-sizing: border-box; }

With border-box, width includes padding and border, so layout arithmetic stops needing a calculator.

Section 6

Colour and background

There are several ways to write a colour: #5ce6b4, rgb(92 230 180), hsl(160 76% 63%), or a keyword such as white.

#5ce6b4
#7aa7ff
#ffc45c

A background can also be a gradient or an image:

two kinds of background 
/* a gradient */
.hero {
  background: linear-gradient(120deg, #5ce6b4, #7aa7ff);
}

/* an image, tiled */
.pattern {
  background-image: url("../images/pattern.svg");
  background-size: 46px 46px;
  background-repeat: repeat;
}

Note the path: a URL written inside style.css is relative to the stylesheet, not to the page. So css/ has to climb one level: ../images/pattern.svg. I marked this again on the practice page.

Section 7

Typography

text on the whole page 
body {
  font-family: "Segoe UI", "Microsoft YaHei",
               "PingFang SC", system-ui, sans-serif;
  line-height: 1.75;
  font-size: 16px;
}
  • A font stack is a wish list, with sans-serif as the last resort.
  • Latin font first, CJK font second gives good Latin letters and correct Chinese characters from the same stack.
  • Line height 1.6–1.8 for body text; headings can be tighter.
  • Sizes in rem respect the visitor's browser setting, pixels do not.
Section 8

Flex and Grid

Two layout tools, one sentence apart: Flex arranges a line (one dimension), Grid arranges an area (two dimensions).

Flex: the navigation bar

why the menu is horizontal 
.nav {
  display: flex;
  align-items: center;      /* vertical centring */
  flex-wrap: wrap;          /* wrap when it runs out of room */
  gap: 10px 18px;           /* row gap / column gap */
}
.brand { margin-right: auto; }  /* brand left, links right */

Grid: three cards in a row

the cards on the home page 
.grid { display: grid; gap: 18px; }
.cols-3 {
  grid-template-columns: repeat(3, minmax(0, 1fr));
}

1fr means “one share of the free space”, so three shares are three equal columns. The minmax(0, 1fr) instead of plain 1fr stops long code from pushing a column wider than its share — a detail I only found when writing the notes pages.

Section 9

Responsive design

Responsive means one HTML file that works on every screen. Three ingredients: the viewport tag, relative units, and media queries.

the two breakpoints of this site 
/* tablet: three columns become two, card moves above */
@media (max-width: 940px) {
  .cols-3 { grid-template-columns: repeat(2, minmax(0, 1fr)); }
  .hero { grid-template-columns: 1fr; }
  .card-preview { order: -1; }
}

/* phone: everything one column */
@media (max-width: 700px) {
  .cols-2, .cols-3, .gallery { grid-template-columns: 1fr; }
  .nav ul a { padding: 7px 10px; font-size: .86rem; }
}

How to check: drag the window narrower and watch for a horizontal scrollbar or text escaping its box.

Section 10

Transitions and animation

transition animates a change of state; animation with @keyframes runs something on its own. This site uses both:

transition on hover, animation on load 
.card { transition: transform .18s, box-shadow .18s; }
.card:hover { transform: translateY(-3px); }

.progress > span {
  animation: grow 1.4s ease-out both;
}
@keyframes grow { from { width: 0; } }

I also added @media (prefers-reduced-motion: reduce), which drops animation to almost zero if the visitor asked the system for less motion. Three lines, and the site stops being uncomfortable for people who get motion sickness.

Section 11

Custom properties

The most useful discovery of the whole course: define a colour once, use it everywhere.

the top of css/style.css 
:root {
  --ink: #080d14;
  --text: #e9eff7;
  --accent: #5ce6b4;
  --radius: 14px;
}

body { background: var(--ink); color: var(--text); }
.card { border-radius: var(--radius); }

Two benefits. Recolouring the site is one edit in :root. And inside @media (prefers-color-scheme: light) I just reassign the same variables, so the whole site follows the operating system's light or dark setting — with no JavaScript and no toggle button.

Why there is no theme switch button

Because a button needs JavaScript to remember the choice. The task is HTML and CSS only, so I let the operating system decide: pick light mode in Windows, the site is light. That is more honest than a button that forgets.
