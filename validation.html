Validation: what I checked, and what it found

“It looks fine in my browser” is not a test. This page is the evidence: the files were sent through the W3C validator, every link was checked, the layout was measured at five widths, and the keyboard was used instead of the mouse. Below are the actual results, including the mistakes the validator caught and what I changed.

What the validator caught the first time

Three real problems, all of them the same family: heading levels that skipped a step.

  1. A h3 straight after the page h1

    The profile card in the hero used <h3> for my name, so the outline jumped from level 1 to level 3. Fixed by making it an h2 — the card is a section of the page, not a subsection of nothing.

  2. h4 in the footer after an h2

    The footer column titles (“Pages”, “About”) were h4, which skipped level 3. They are now h2 inside the footer, and the small uppercase look comes from CSS, not from the heading level.

  3. article and section without a heading

    The notes pages wrapped everything in an article whose headings live inside the child section elements, and the contents block was a section with only a nav inside. Both were changed to plain div: if there is no heading, the element is not a section.

8 · accessibility

Accessibility checks

The course material points at the W3C “Easy Checks”. These are the ones this site passes, and how.

Easy checks, and where they are implemented
CheckHow this site does it
Page has a title Every page has its own <title>; the tab never says “untitled”.
Page language declared <html lang="en"> on all seven pages.
Headings convey structure One h1, no skipped levels — that is exactly what the validator enforced.
Images have text alternatives Every <img> has a descriptive alt; decorative shapes are CSS, not images.
Keyboard access The first Tab stops on a “Skip to content” link; every link and form field is reachable without a mouse.
Visible focus :focus-visible draws a dashed outline in the accent colour, so you can see where you are.
Current page marked aria-current="page" on the active menu item, and the navigation has aria-label="Main navigation".
Contrast Body text is near-white on a near-black background; the accent colour is only used for large text, borders and links.
Motion @media (prefers-reduced-motion: reduce) reduces transitions to almost nothing.
Colour scheme @media (prefers-color-scheme: light) re-assigns the variables, so the site follows the operating system.
Table markup Tables use caption, thead and th scope, so a screen reader can announce the column.

How I tested it: pressed Tab from the top of each page and noted the order, then zoomed the browser to 200 % and checked that nothing overlapped or disappeared.

9 · comments

How the code is commented

The last study step asks for commented code. The rule I follow: a comment explains why, never what the tag is. Anyone can see that <h2> is a heading; what is useful is knowing which part of the page it opens.

HTML — a marker above each region
<!-- ===== Hero ===== -->
<section class="wrap hero">
  <h1>…</h1>

  <!-- The card on the right is built
       entirely with HTML and CSS -->
  <div class="card-preview">…</div>
</section>
CSS — numbered sections, one idea each
/* ---------- 4. Header and navigation ---------- */
.nav {
  display: flex;
  flex-wrap: wrap;   /* wraps instead of overflowing */
  gap: 10px 18px;
}

/* The current page is marked with aria-current,
   an HTML attribute, so no script is needed */
.nav ul a[aria-current="page"] { … }
  • Every HTML file starts with a comment naming the page, and each major region has a marker.
  • style.css opens with a table of contents of its 15 numbered sections, then each section begins with the same heading.
  • Explanatory comments sit next to the tricky lines: minmax(0, 1fr), the :target tab trick, the relative path in a background image.
  • No commented-out code is left behind: dead CSS was deleted, not hidden.

To see it, open any page and press Ctrl + U (view source) or open css/style.css in the repository.
